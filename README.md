# DissSystem

Програмна система до дисертації: моделювання на основі нечітких когнітивних карт (НКК) і генетичного алгоритму (ГА).

Реалізовано (логіка перенесена з `legacy/` і відтворює результати оригінальних скриптів):

| Задача | Шкала | Приклад | Оригінал |
|---|---|---|---|
| Емпіричне моделювання за даними + ГА [W \| T], ранги I(Cᵢ) | [0, 1] | ІХС | `legacy/med_experiment.py` |
| Прогнозування (прямий вивід) | [−1, 1] | автопідприємство | `legacy/transport_forecast.py` |
| Діагностика (зворотний вивід, ГА) | [−1, 1] | автопідприємство | `legacy/transport_diagnosis.py` |
| Метод найменшого впливу (Сааті) + налаштування ГА | [−1, 1] | автопідприємство | `legacy/saaty_main.py`, `legacy/saaty_tuning.py` |

## Встановлення (macOS)

```bash
cd ~/Desktop/PhD/DissSystem
```

## Інтерфейс (Streamlit)

```bash
streamlit run app/main.py        # відкриється http://localhost:8501
```

Покроковий майстер без програмування. Перший крок кожного проєкту — **Проєкт**: назва, шкала значень
концептів **[0, 1] або [−1, 1]** і (для моделі за даними) тип результату — **класи або число**.

- **Модель за даними**: Проєкт → Дані (CSV, ролі стовпців, «що краще») → Модель (граф, матриця ваг) →
  Налаштування (ГА, збіжність, матриця класів або R²) → Використання (результат нового випадку, що-якщо, пакетно,
  ранги впливу) → Звіт.
- **Експертна модель**: Проєкт → Концепти → Зв’язки (ранги Сааті 1–9 або числові ваги) →
  Налаштування за сценаріями (необов’язково) → Використання (прогноз, пошук причин) → Звіт.
- **Збіжність** (вкладка на кроці «Використання» обох майстрів): та сама карта моделюється з різними
  правилами виведення (огляд Nápoles et al., 2026: формули (1), (3), (5), (6)) і пороговими функціями
  (табл. 1: двозначна, ступінчаста, тризначна, tanh, сигмоїда, масштабувальна, експоненційна нормована) —
  поруч із базовим варіантом «як у моделі» (без порогової функції + нормування (11)). Таблиця: дійшла чи ні
  карта до нерухомої точки, цикли, розбіжність, кроки, теоретичні умови (ρ(W), стиск, теореми 3, 6, 10),
  якість з нормуванням і без; графік виходу в стаціонарний стан для обраного випадку. Формули моделі не змінюються.
- **Мої проєкти** — на стартовому екрані. Проєкти зберігаються **у браузері користувача (localStorage)** на його
  комп’ютері: дані, налаштування, результати ГА. Автоматично — при переході між кроками, вручну — кнопкою
  «Зберегти проєкт». Відкритий проєкт відновлюється повністю, без повторного запуску ГА. Іконки в рядку:
  завантажити файл проєкту (.json) і видалити (з підтвердженням). Файл від колеги відкривається через
  «Відкрити файл проєкту». На хостингу кожен користувач бачить лише свої проєкти — сервер їх не зберігає.
- Сховище прив’язане до адреси (браузер + `http://localhost:8501`): у іншому браузері чи на іншому порту
  список буде порожнім. Для перенесення — файл проєкту. Обсяг localStorage ~5 МБ: великі набори даних краще
  зберігати файлом.

**Шкала.** Розрахунок кожного методу ведеться у його «рідній» шкалі, як у статтях: перфектність — [0, 1],
експертна НКК — [−1, 1]. Шкала проєкту визначає, як значення вводяться і показуються; перетворення лінійне
(`core/scale.py`), тож вибір шкали не змінює результатів.

## Запуск без інтерфейсу

```bash
pytest                    # швидкі тести (~30 с)
pytest -m slow            # повні прогони ГА та інтерфейсу (~4 хв)

python -m core.run examples/ihd/config.yaml            # як legacy (~1 хв)
python -m core.run examples/ihd/config.yaml --fast     # швидкий режим (~10 с, для ІХС — ті самі результати)

python -m core.run examples/transport/config.yaml                    # прогноз + діагностика + Сааті (~45 с)
python -m core.run examples/transport/config.yaml --task forecast    # лише прогноз
python -m core.run examples/transport/config.yaml --task diagnosis   # лише зворотний вивід (~7 с)
python -m core.run examples/transport/config.yaml --task expert      # Сааті + налаштування (~35 с)
```

Якщо `python` у вашому терміналі запускає системний Python, використовуйте `.venv/bin/python -m core.run …`.

Результати пишуться в `results/ihd/`: `Table_3…7`, `W_initial.csv`, `W_optimized.csv`,
`convergence.csv`, `importance.csv`, графіки `optimization_dynamics.png`, `concept_ranking.png`.

Результати автопідприємства — у `results/transport/{forecast,diagnosis,expert}/`.

Опції CLI: `--out <папка>`, `--task`, `--generations N`, `--fast`, `--no-plots`, `--no-importance`.

## Нова задача без нового коду

**Дані «входи → клас» (як ІХС):**
1. Покладіть CSV у `examples/<назва>/data.csv` (стовпці-входи + стовпець класу 1..m).
2. Скопіюйте `examples/ihd/config.yaml`, змініть `concepts` (id = назва стовпця, `rule` a/b/c),
   `output.column`, `output.classes`, `initial_thresholds` (m−1 штук).
3. `python -m core.run examples/<назва>/config.yaml`

**Експертна НКК у шкалі [−1, 1] (як автопідприємство):** скопіюйте `examples/transport/config.yaml`,
змініть `concepts` (role: cause / effect), матрицю `W`, сценарії діагностики, `train.csv`.
Ранги Сааті можна задати напряму в `expert.ranks`.

## Структура

```
core/
  fcm.py           рекурентна формула (4): фіксовані кроки (ІХС) і до стаціонарності (УДС)
  normalize.py     перфектність, формула (8)
  weights_data.py  ваги з даних, формули (10)–(15) + структурні обмеження
  metrics.py       класифікація за порогами, MAD/MSE, матриця помилок
  ga.py            обгортка pygad
  tuning.py        ІХС: хромосома [W | T]; УДС: налаштування ваг «багато входів – багато виходів»
  weights_expert.py метод найменшого впливу (Сааті), інтервали ваг
  diagnosis.py     прогноз і зворотний вивід (ГА) у шкалі [−1, 1]
  gds.py           конфіг і звіти для УДС
  importance.py    ранги I(C_i)
  convergence.py   перевірка збіжності: правила (1)–(6) і порогові функції огляду Nápoles et al. (2026)
  experiment.py    повний цикл
  reports.py       таблиці 3–7, графіки
  config.py        завантаження YAML
  run.py           CLI
  model_io.py      модель для використання (прогноз із сирих даних)
  scale.py         шкали [0, 1] / [−1, 1]
app/
  main.py          точка входу Streamlit
  ui.py            стилі, кроки, графіки
  projects.py      сховище проєктів у браузері (localStorage, компонент st.components.v2)
  views/           start.py, empirical.py (майстер «за даними»), expert.py (експертна модель),
                   convergence.py (вкладка «Збіжність»)
examples/ihd/      дані (N=65) і конфіг
examples/transport/ матриця W, сценарії, train.csv, конфіг
tests/             тести + golden/ (виходи legacy-скриптів)
legacy/            оригінальні скрипти досліджень (не змінювати)
docs/formulas.md   відповідність «стаття → код», відомі розбіжності
```

> ⚠ Медичні дані використовуються лише для дослідження. Система не є клінічним інструментом.
