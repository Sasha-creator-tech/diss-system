## Теоретична база (статті)
1. **Діагностика (зворотний вивід)** — НКК як модель "багато входів – багато виходів"; причини (входи) відновлюються за відомими наслідками (виходами) генетичним алгоритмом: min ||X_G − X̂_G(X_U)||. Ранжування причин з урахуванням/без урахування взаємодій. Приклад: автопідприємство (10 концептів: 5 причин + 5 наслідків).
2. **Проєктування й налаштування НКК за експертними оцінками** — метод найменшого впливу (9-бальна шкала Сааті, без повної матриці парних порівнянь) + налаштування ваг ГА. Приклад: автопідприємство.
3. **Емпіричне моделювання за даними** (EMP-PAVLOV) — з таблиці "входи–вихід": нормалізація через нечітку перфектність (формула 8, параметри b, c=0.389), подібність і знак впливу (10–12), min-відстані (13–14), ваги дуг (15), інтервали ваг, налаштування МНК+ГА (хромосома: ваги W, параметри b_i, пороги класів t_1..t_{m-1}). Приклад: диференціальна діагностика ІХС, N=65, 12 параметрів, 6 класів d1..d6.
4. **Загальна стаття: прогнозування та діагностика в УДС** — стандартна практика НКК: пряме прогнозування (forward inference) + зворотний вивід.

Тексти статей лежать у проєкті claude.ai "Dr. Rusavskiy: PhD Preparetion" (читай через Projects, не шукай на диску).

## Спільне математичне ядро
- Матриця впливів W0 (n×n, діагональ 0), вага w_ij ∈ [−1,1].
- Рекурентна формула: X^{k+1} = X^k ⊕ (X^k ⊖ X^{k−1})·W0, X^1 = X^0 ⊕ X^0·W0; стаціонарність: |x_i^l − x_i^{l−1}| < ε.
- Прогноз: вхідні концепти задаються, вихідні стартують з мінімуму (−1 у шкалі [−1,1]; 0 у шкалі [0,1]); у стаціонарному стані — нормування за min/max.
- ⚠ Є ДВІ шкали концептів: [−1,1] (статті 1, 2, 4) і [0,1] з перфектністю (стаття 3). Система має підтримувати обидві, явно позначати активну шкалу в конфігу й UI, не змішувати мовчки.
- Вихід-клас (діагноз): інтервали [0,t1],[t1,t2],… — пороги t налаштовуються.

## Структура проєкту
```
core/                 чистий Python + numpy, БЕЗ імпортів streamlit; усе тестується
  fcm.py              рекурентна формула, стаціонарний стан, прогноз
  normalize.py        перфектність (типи a/b), min-max
  weights_data.py     вилучення ваг з даних (стаття 3)
  weights_expert.py   метод найменшого впливу / Сааті (стаття 2)
  ga.py               універсальний ГА (хромосома = ваги [+ b] [+ пороги t]); параметр seed
  tuning.py           налаштування (МНК, цільові функції)
  diagnosis.py        зворотний вивід, ранжування причин
  metrics.py          MSE, MAD, accuracy, матриця помилок
  model_io.py         формат моделі (JSON): концепти, ролі, W0, інтервали, нормалізація, класи
app/                  Streamlit-інтерфейс (app/main.py + pages/), лише викликає core/
examples/             ihd/ (ІХС: CSV + config), transport/ (автопідприємство)
tests/                pytest; відтворюють числа зі статей
docs/                 відповідність "формула в статті → функція в коді"
requirements.txt      numpy, pandas, matplotlib/plotly, streamlit, pytest
README.md             як встановити й запустити
```
Нова задача = CSV + конфіг (YAML/JSON) з описом концептів, ролей, типів перфектності, класів, інтервалів ваг, параметрів ГА. Без написання нового коду.

## Запуск локально (має працювати з коробки)
```
python -m venv .venv && source .venv/bin/activate   # Windows: .venv\Scripts\activate
pip install -r requirements.txt
pytest                      # перевірка ядра
streamlit run app/main.py   # інтерфейс
```
Також корисні CLI-скрипти для відтворення результатів статей без UI (напр. `python -m core.run examples/ihd/config.yaml`).
README підтримуй актуальним при кожній зміні способу запуску. Автор працює на macOS.

## Інтерфейс Streamlit (потік майстра)
Дані/Експерт → Проєктування (граф НКК, матриця W) → Налаштування (ГА, графік збіжності, матриця помилок до/після) → Використання (прогноз, діагноз, зворотний вивід, ранжування, what-if) → Експорт (JSON моделі, таблиці CSV, графіки PNG).
Довгі обчислення ГА: показувати прогрес, кешувати результати (`st.cache_data`), стан тримати в `st.session_state`.

## Поточний стан (оновлювати)
- Ядро `core/` перенесене з усіх 5 legacy-скриптів і відтворює їх (див. README, `docs/formulas.md`):
  ІХС (`legacy/med_experiment.py`), прогноз/діагностика автопідприємства (`legacy/transport_*.py`),
  метод Сааті + налаштування (`legacy/saaty_*.py`).
- Конфіги: `examples/ihd/config.yaml` (task: empirical), `examples/transport/config.yaml` (task: gds).
- Seed: у legacy діагностики/Сааті seed не задавався → у ядрі додано `seed`; еталони для них — з копій legacy з тим самим seed (`tests/golden/transport/legacy_*_seeded.py`).
- Інтерфейс `app/` (Streamlit): обраний варіант A — покроковий майстер; з варіанта B взято вкладки прогнозу/діагностики.
  Граф лише для перегляду (graphviz), редагування — таблицями (`st.data_editor`). Світла тема, IBM Plex, синій #1F4FC9 (+) / помаранчевий #C2620C (−).
  Макети: claude.ai artifact «DissSystem — макети інтерфейсу».
- Тести інтерфейсу: `tests/test_app.py` (Streamlit AppTest).
- Майстри мають перший крок «Проєкт»: шкала [0, 1] / [−1, 1] (лише представлення, `core/scale.py`) і тип виходу
  (класи / число) для моделі за даними. Граф — компактне коло (neato, фіксовані координати), вихід у центрі.
- Проєкти зберігаються в localStorage браузера користувача (`app/projects.py`, міст через st.components.v2;
  після кожного збереження потрібен st.rerun, щоб черга дійшла до браузера). Таблиця «Мої проєкти» на старті,
  автозбереження при переході між кроками; відкритий проєкт відновлює результати без ГА
  (`experiment.rebuild_result`, `tuning.mimo_result`). У тестах — DISSSYSTEM_STORAGE=memory.
- UI-рішення автора: шкала не показується в шапці (лише на кроці «Проєкт»); граф показує всі зв’язки (без повзунка).

## Порядок роботи
1. Спочатку `core/` + тести, потім UI. Одна функція — одна формула/ідея з номером формули і статті в docstring.
2. **Практика — у коді, стаття — теоретична основа.** Еталон поведінки — скрипти в `legacy/`; рефакторинг має відтворювати їхній вихід побайтово (еталони в `tests/golden/<задача>/`, ГА — з фіксованим seed).
3. Автор поступово додає свій готовий код досліджень. Перед переписуванням: прочитай, коротко опиши, як він працює, потім виносити в `core/`. Оригінали не видаляти — класти в `legacy/`. Спочатку запустити оригінал і зберегти його вихід як golden.
4. Розбіжності код ↔ стаття не "виправляти" мовчки: за замовчуванням — як у коді, альтернатива (як у статті) — опцією конфігу; фіксувати в `docs/formulas.md`.
5. Зміни невеликими кроками, після кожного — запускай `pytest` і коротко повідомляй результат.
6. Відповідати стисло, українською. Терміни: НКК, концепт, вага дуги, зворотний вивід, ГА.
7. Медичні дані — лише для дослідження; в UI розміщувати застереження, що це не клінічний інструмент.
8. Не комітити персональні дані пацієнтів у публічний репозиторій; приклади — тільки ті, що вже є у статтях.
